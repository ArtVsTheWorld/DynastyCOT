# Update 4 development: audience model, 2.1.0

A larger stadium no longer gives a program more interested spectators. A fixed audience foundation is adjusted against current prestige, stadium atmosphere, completed-season results and AP rank at 40/30/20/10. The newest completed season gets 50% of the result weight, then 30% and 20%. Missing history and unavailable AP are omitted. TeamBuilder results before dynasty Year 0 do not count.

Known schools use a frozen 2025 attendance/five-year reference and calibration adjustment. Custom and unmapped schools use a robust peer estimate by prestige/atmosphere. Native IsTeamBuilder overrides an inherited school ID when choosing that path. The foundation is stored separately for each native Franchise.LeagueID and program record identity in the plugin's own History folder. It is reused after restarts, and current support is compared with the same reference rather than multiplying last year's audience. An earlier save rebases a first-observed peer foundation that would otherwise come from its future. A late first install does not erase earned success for a native school whose initial history was missing.

The existing event boost ranges and combined cap remain, as do the arrival functions, school groups, deadlines, Fuller option, protected showcase events and unsupported-mode/postseason/resume paths. Ordinary opponent/current-season strengths now act against a fixed audience reference. Weather and variation act on spectators; a capacity-based breakout target becomes bounded temporary interest. The former peak percentage floor does not create extra spectators. Existing departure floors still do not refill native empty seats.

Read-only native integration uses the database table lookup/FIRST ABI for Franchise, then borrowed native records for TeamSeasonStats. Enum labels/ordinals for LeagueID, IsTeamBuilder, TeamSeasonStats, WINS, LOSSES and TIES match the preserved patched image. Invalid identity/history/storage keeps EA turnout. Seed failure clears older launch inputs. No native pointer is serialized. Foundation disk writes run on the worker with pending-file replacement, and failure is logged. No new per-play, audio or camera memory reads were introduced.

Validation includes the full automatic build suite, 14 Python tests, focused post-review audience/native/logging/launch/arrival checks, isolated MMC packaging/resource/loader verification, and installation/rollback fixtures that preserve the foundation file. Six-season production-policy simulations contain 48 season rows and 96 day/opener plans across improvement, flat support, decline, small/large venues and stadium expansion. The foundation is serialized and reloaded each season. Future season results are not used. Grade/AP trajectories are hypothetical inputs, not predictions of EA progression.

Private evidence and report: Build/Update4Implementation. The detailed report shows audience counts, old/new ordinary peaks, old/new night openers and kickoff fullness. The native history/identity query and attendance-to-visible-seat agreement still require a live fresh-launch/restart/second-dynasty check. No game, installed plugin, settings or save was changed, and nothing was published.
