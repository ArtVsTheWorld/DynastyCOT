# 0.1.8 Social Media renderer hotfix

The live 0.1.7 page showed its header and filters but no post cards. The captured active feed contained 1,406 stored posts, 40 For You selections, three archived/current weekly editions and valid sidebar metadata. Logs showed the experimental list renderer active and scope changes returning posts. The production list-group substitution is the leading rendering regression; this candidate restores the native per-post container path used before 0.1.7. Live confirmation still requires restarting into this candidate.

## Implementation

- Remove the production ListFeed build flag and make the native post renderer explicit. Both the build script and compiler reject the unverified list mode.
- Record the renderer contract in native build inputs and the package manifest; packaging rejects unsupported rendering modes.
- Retain the 0.1.7 budget, news protection, full scope lists, one weekly selector entry, short card headers and published history.
- Temporarily disable the sidebar renderer. Preserve its factual summary metadata; a verified native sidebar remains outstanding work.

- The copied live feed validates across all three editions and every dynamic scope. Its selected view produces one native donor-compatible container per post, with default linkage and stable coordinates. This is a data/ABI test, not a rendered-game screenshot.
- Package verification passes, including runtime source matches, all 16 module selections and 106 core checks. All 978 standalone source inputs remain unchanged.
- 105 installer, 34 real setup-window/engine and 95 exact 0.1.7-to-0.1.8 updater/rollback checks pass in isolated fixtures. Metadata/provenance/privacy checks pass. The older 0.1.6 Defender block is separate and remains documented in earlier notes.

Initial build attempts hit an atomic-commit error in an unchanged isolated settings stress test. An instrumented test rerun and the final full build passed; test-only Win32 diagnostics now retain the error code if it recurs. No production persistence behavior was changed.
