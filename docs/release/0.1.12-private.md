# Dynasty COT 0.1.12 private test candidate

Fixes the Player Analytics card path in Beyond the Field. The table could show valid player names and grades while the card showed a blank portrait and `-1` values.

- Removed the Analytics hook on the unrelated Dynasty-information callback. Card responses now go through the existing Fog-owned roster-card callback, with one owner.
- Known players in the selected Analytics view receive a fresh native card object populated from the captured player record. Names, portrait IDs, team colors/logo, position, OVR, class, jersey, measurements and known hometown data stay tied to the selected player after sorting and National/team/week changes.
- Missing or unrelated keys retain the native fallback. Fresh objects prevent the preceding player's fields from carrying over. Unavailable archetype/ability information is not fabricated; optional details still need live review.
- The existing Fog conversion runs after the Analytics response, preserving the grade/color settings path. Two native allocation helpers have exact instruction gates. No additional shared hook, helper process, grade-model change or save write is introduced.
- Diagnostic logging is bounded to the first 16 successful card fills and eight deferred keys.

All 0.1.11 editorial changes remain included. Post budgets, published history, account identities, the four module choices and other modules retain their behavior.

Close the game and MMC before installing this candidate. A restart is required because the fix changes native code; it cannot update the already loaded page. Use Backups or the retained 0.1.11 installer to roll back the payload. Settings/history are retained; rollback does not rewind a Dynasty save.

This candidate is built locally. No live installation or publication is performed. Read-only evidence identified the faulty callback; live acceptance of the replacement, complete card details and the user's exact AIO/TeamBuilder combination remains pending. See [verification](../verification-0.1.12.md).
