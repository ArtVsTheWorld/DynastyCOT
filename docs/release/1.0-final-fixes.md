# 1.0 final recruiting and Analytics fixes

These changes remain part of the unpublished 1.0 release. The first 1.0 installer/package is retained locally for rollback and comparison; it was not replaced in place or installed by the build.

## Recruiting money warning

A read-only live asset capture reproduced the cause. The stock recruiting wallet and offer-list methods had their expected code hashes, but their unused classes still contained the game's unlinked constant-pool sentinels. The active offer/hours class had a linked pool. The old adapter tried to validate all three classes together, so an unused sibling disabled the whole group.

The three classes now use separate adapter banks. Each still requires its own exact method/body, frame, constant-pool and ownership checks. No sentinel is initialized or accepted as a real pool. Existing AIO adapters remain available. The NIL toggle formatter and all its generated bytecode are unchanged.

A bounded session-only adapter successfully admitted the active native class twice without weakening the checks. The user confirmed that recruiting money labels stayed in $K/$M format. Temporary broad tracing added UI overhead; it was replaced with a narrow, in-process-header path, after which the user confirmed recruiting responsiveness was normal again. Development DLLs are excluded from the release package.

## Analytics player-card Ratings delay

An armed Analytics return ticket caused every script setup to perform a fresh Dynasty identity walk before checking whether the script could be a Roster return handler. Regular Roster cards did not take this path.

The adapter now checks the exact native/owned return-frame shapes first. It performs the same fresh Dynasty scope check immediately before any actual return admission. Invalid identity, foreign bodies and ownership conflicts still fail closed.

The equivalent callsite-only fix was tested in the running game using the installed module's proven executable-code fingerprint and an owned, reentrant context wrapper. In busy callback samples with the return ticket armed, original callbacks averaged about 9.68 microseconds; optimized samples averaged about 0.26 microseconds. These are callback costs from unequal activity windows, not identical end-to-end tab timing or an FPS measurement. The user described Ratings as "a bit faster" and confirmed Back returned to Analytics successfully. Complete removal of the perceived tab delay is not claimed.

## Verification

- 48 compiled real-Runtime currency isolation checks: reproduce sentinel-sibling failure; linked-class admission; Off/reuse/restoration; unchanged fingerprints; unrelated frames and tamper rejection.
- 21 compiled production return-dispatch checks: 10,000 unrelated scripts produce no identity walks; native/owned vanilla and AIO frames still require fresh scope/ownership checks.
- 125 same-version upgrade checks compare actual old/new 1.0 payload hashes, preserve settings/history, verify repeat update, inject three failure stages and restore old binaries while retaining later user data.
- The normal full four-module source build and package/installer/updater suites run again for the revised assets. Consult the matching release evidence for their final results.

The new package still needs a clean restart to confirm the old warning does not recur without session-only test adapters. Publication remains held. No game save or native budget/statistic was edited during this investigation.
